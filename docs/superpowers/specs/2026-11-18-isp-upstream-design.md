# ISP 美国前置自动切换

## 需求与约束

修复导入订阅后 ISP 的 `dialer-proxy` 指向不存在代理组的问题。保留四家 VPN 的全部节点和两个 ISP 节点，各自继续使用独立本机 SOCKS5 端口，沿用 `data/ports.json` 的映射。仅管理本项目进程，不更改系统代理、TUN 或用户其他 Clash 配置。订阅、密码、测速原始配置均不写入文档或 Git。

## 方案

建议使用 mihomo 原生 `url-test` 组：从四家 VPN 中筛选美国节点，排除 ISP、已经带有前置依赖的节点及非美国城市（例如哥斯达黎加 San José）。两个 ISP 共用此组，保持各自 ISP 出口。启动时测速，之后每 30 秒检测一次，单节点探测超时 3000ms，容差 0ms，关闭懒惰检测。检测失败后由 mihomo 在可用候选中重新选择；现有 TCP 连接需要重连。

另一种方案是测速后按延迟排序使用 `fallback` 组，仅故障时切换，更稳定但无法持续选择当前最低延迟。直接写死一个前置节点不能满足自动切换要求。

## 实施边界

先做三轮美国节点 HTTP 探测并报告各家最快结果。生成配置时为 ISP 显式创建无循环依赖的前置组；没有合适候选时清晰报错并保留旧服务。为丢失前置组、候选筛选和固定端口增加回归验证；用 mihomo 校验真实订阅生成结果，再验证两个 ISP 的实际连通性和隔离环境下的故障切换。只重启本项目服务。

## 已确认

用户已确认直接采用持续选择最低延迟的 `url-test`，并授权修复及验证。
